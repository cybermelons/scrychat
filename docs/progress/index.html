Open, and deliberately not on the board (4)

These are findings and records, not controls this target has to grow. Each one is excused by name, so a gap in the mapping is a decision a reader can check, not an omission.

  • #44 Data error in two generated deck pages, not a target control: regenerate them. The behaviour that caused it is tracked by #47.
  • #63 Research notes on card-similarity approaches, and the conclusion is to build nothing yet: otag already encodes function, which an oracle-text embedding would duplicate worse. No control follows until that changes.
  • #64 A competitive analysis of other AI deckbuilders. It argues what the product already is, so it pins to no new control; where it names a gap, that gap gets its own issue.
  • #65 A feature inventory of one competitor, filling the undisclosed cells in #64's table. Its output is a doc and a correction diff, so it changes no control here; anything it turns into product work gets its own issue.
The board draws the scrychat surface as the discovery-loop design proposes it, not as it is today, and pins each work item to the control that has to exist for that design to be true.
